## 5. read-100vu에서 1.6초 지연 두 번

- 시각: 22:09:35 전후와 22:09:48 전후 (13:09 UTC). 각각 2–3초 동안 났습니다.
- 영향: 800ms를 넘은 요청이 192건입니다. API 종류와 관계없이 함께 느려졌고, 최대 1.6–1.9초였습니다. 오류는 없습니다.
- 관찰 내용
  - 부하 발생기: 진행 중인 HTTP 요청이 평소 5–15개에서 54–66개로 쌓였습니다. 그동안 발생기 CPU는 오히려 17–31%로 떨어졌습니다. 따라서 발생기 쪽 문제가 아닙니다.
  - 175와 176: 초당 처리 건수가 **같은 초에** 평소 80–90건에서 20–45건으로 함께 떨어졌습니다. 같은 시간대에 오류 로그나 재시작 기록은 없습니다.
- 해석: 두 서버가 동시에 멈칫했으므로, 원인은 공통으로 쓰는 쪽에 있을 가능성이 큽니다. 후보는 MariaDB 171(쓰기 플러시나 버퍼 풀 교체), HAProxy, 네트워크입니다. 원인을 확정하지는 못했습니다.
  - 참고: 실행 동안 `Innodb_buffer_pool_reads`가 69,683 늘었습니다. 버퍼 풀이 128MB인데 `events`는 데이터와 인덱스를 합쳐 126MB까지 커져서, 디스크 읽기가 생기기 시작한 상태입니다.
- 권고
  - MariaDB `innodb_buffer_pool_size`를 늘리는 것을 검토하세요. 서버 메모리 사용률은 18%로 여유가 있습니다.
  - MariaDB exporter를 복구하세요. 연결 수, 스레드 수, 잠금 대기 값이 계속 미측정이어서 이런 순간을 분석할 수 없습니다.
