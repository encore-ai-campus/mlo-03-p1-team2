# 관리자 공연 관리 구현 계획

2026-11-05 관리자 기능의 작업 계획과 당시 검증 기록이다.
현재 기능·계정 준비·DB 적용 절차는 [관리자 안내](../../admin.md)를 따른다.
아래 실행 제한은 당시 작업 범위이며 새로운 작업에 대한 지시가 아니다.

## 목적과 구현 방향

기존 웹 회원 중 관리자에게 공연 조회·등록·수정·삭제 화면과 API를 제공한다.
기존 JWT 인증에 DB의 `users.is_admin` 검사를 추가하고, 관리자 경로와 API를 분리한다.
일반 고객의 공연 조회·예매·인증 기능은 유지한다.

사용 기술은 FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, Vue 3, Vue Router, Pinia다.
당시 구현은 기존 작업 폴더에서 Superpowers의 `executing-plans` 절차로 진행하도록 계획했다.

## 작업 범위와 제약

- DB 변경은 `users.is_admin` 추가로 제한하고 기존 회원의 기본값은 `false`로 둔다.
- 관리자 지정은 기존 회원을 대상으로 서버 CLI에서만 수행한다.
  회원가입·프로필 수정 요청으로 관리자 권한을 얻을 수 없게 한다.
- 예매·결제 이력은 삭제하지 않는다. 예매가 있는 공연 삭제는 `409`로 거절한다.
- 기존 포스터·폰트·색상·폼·모달을 재사용하고 새 스타일은 해당 화면·컴포넌트 안에 둔다.
- 당시 사용자 지시에 따라 화면 실행·기능 테스트·빌드·실제 DB 반영은 수행하지 않는다.

## 작업 내역

- [x] 관리자 컬럼·마이그레이션·회원 응답·권한 의존성·권한 부여 CLI 추가
- [x] 관리자 공연 목록·상세·등록·수정·삭제 API와 입력·응답 스키마 추가
- [x] 관리자 라우터 가드·메뉴·인증 API 도우미 추가
- [x] 공연 관리 화면·등록/수정 폼·삭제 확인·기존 카드 미리보기 추가
- [x] 프론트엔드·백엔드 안내에 관리자 문서 연결
- [x] 정적 코드 검토와 문법·변경 범위 확인

## 주요 검토 항목

- 일반 회원이나 임의의 요청 필드로 관리자 권한을 얻을 수 없는가
- 날짜·회차·포스터·가격이 기존 예매 정보 및 정수 금액 범위에 맞는가
- 삭제 실패 시 찜·조회 기록 변경이 롤백되고 기존 예매 이력이 보존되는가
- 검색·페이지 변경 중 이전 응답이 최신 목록을 덮어쓰지 않는가
- 저장 중 중복 실행과 관리자 권한 회수에 화면·서버가 일관되게 대응하는가

## 당시 검증 결과와 한계

Python 10개 파일의 AST 구문 분석, Vue 3개 컴포넌트의 구문 분석,
JavaScript 5개 모듈의 문법 검사와 `git diff --check`를 통과했다.
이 수치는 당시 검사 기록이며 이번 문서 정리에서 다시 실행한 결과가 아니다.

검토 과정에서 가격 상한 계산으로 최대 예매 금액 초과를 방지하도록 수정했다.
날짜를 바꾸지 않은 공연 수정은 기존 표시 기간 문구를 보존하도록 했다.

앱·서버 실행, 기능 테스트, 빌드, 실제 DB 작업은 수행하지 않았다.
정적 검사는 실제 동작 검증을 대신하지 않으며 권한 경계·회귀 여부 등은 별도 확인 대상이다.
