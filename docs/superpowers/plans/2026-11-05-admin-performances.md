# 관리자 공연 관리 구현 계획

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the current workspace. 사용자의 기존 지시에 따라 화면·테스트 실행은 생략한다.

**Goal:** 기존 웹 회원 중 관리자에게 공연 조회·등록·수정·삭제 화면과 API를 제공한다.

**Architecture:** 기존 JWT 인증에 DB의 `users.is_admin` 검사를 추가한다. 관리자 경로와 CRUD API를 별도로 두고 기존 고객용 공연·예매 API를 유지한다.

**Tech Stack:** FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, Vue 3, Vue Router, Pinia.

**Spec:** `docs/admin.md`

## Global Constraints

- DB 변경은 `users.is_admin` 추가로 제한하고 기존 회원은 `false`로 둔다.
- 관리자 지정은 기존 회원 대상 서버 CLI로만 제공한다.
- 가입·프로필 수정에서 관리자 권한을 받을 수 없게 한다.
- 예매·결제 이력은 삭제하지 않는다. 예매가 있는 공연 삭제는 409다.
- 기존 포스터·폰트·색상·폼·모달을 재사용하고 새 스타일은 화면·컴포넌트 내부에 둔다.
- 화면·테스트·빌드·실제 DB 반영을 실행하지 않는다.

## Review Focus

- 일반 회원과 임의의 요청 필드가 관리자 권한을 얻을 수 없는가.
- 날짜·회차·포스터 이미지·가격이 기존 예매와 정수 금액 범위에 맞는가.
- 삭제 실패 시 찜·조회 기록도 롤백되고 기존 예매 이력이 남는가.
- 목록 검색·페이지 변경 중 이전 응답이 최신 결과를 덮지 않는가.
- 저장 중 중복 실행과 권한 회수에 화면·서버가 일관되게 대응하는가.
