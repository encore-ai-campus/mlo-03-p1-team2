# 중단된 부하 테스트 재개 계획과 복구 기록

2026-11-06 원격 연결 중단 후 `load-20261106-prepare` 실행을 복구하기 위한 계획과 당시 기록이다.
현재 실행 조건은 [부하 테스트 계획](../../loadTestPlan.md), 후속 측정·중단 결과는
[부하 테스트 결과](../../loadTestResult.md)를 따른다. 아래 기록은 실행 재개 지시가 아니다.

## 목적과 재개 원칙

사용자가 승인한 실행을 기존 계정·저장 데이터·검증 증거·쓰기 한도를 보존하며 재개한다.
새 쓰기를 허용하기 전에 입력·계정 신원·DB 증거·공유 예산이 일치하는지 감사한다.

완료 단계와 중단 당시 측정값은 보존한다. 기존 계정으로 다시 인증한 뒤 중단 단계를
재측정하고, 감시·중단 기준을 유지하며 남은 단계로 진행한다.
개별 거래를 재실행하거나 기준선·쓰기 예산을 초기화하지 않는다.

## 당시 작업 내역

- [x] 처리 결과가 확정되지 않은 쓰기, 증거 불일치, 실패 단계, 계정 누락,
  잘못된 단계 순서를 거절하는 회귀 테스트 추가. 정상 중단은 남은 단계만 선택하는지 확인
- [x] 기존 실행 ID·기준선·예산을 사용하는 `--resume-load` 준비·실행 기능 추가.
  쓰기 전 복구 스냅샷과 중단 단계 요약을 저장하고, 완료한 정합성 시험은 반복하지 않음
- [x] 실행기 검사 33개 통과 후 실제 DB·모니터링 감사.
  종료가 확인된 프로세스 잠금만 보관 처리하고 출력 파일을 유지하는 백그라운드 프로세스 1개 시작
- [ ] 완료 또는 필수 중단까지 관찰하고 실측값·목표 미달·한계를 결과 문서에 기록

마지막 항목의 체크 상태는 당시 원문 기록을 유지했다.
후속 결과 문서에는 `mixed-200` 단계에서 API별 임계값 초과로 중단된 결과가 기록되어 있다.
미체크 항목을 현재의 실행 요청이나 계속 진행해야 할 작업으로 해석하지 않는다.

## 당시 작업 환경과 보존 조건

복구는 당시의 `perf/load-test-20261106` 브랜치에서 진행했다.
현재 브랜치를 지정하는 문장이 아니라 그때 사용한 작업 환경의 기록이다.
기존 작업 폴더의 미커밋 실행기 수정과 Git 제외 자격 증명·산출물이 필요했기 때문이다.
다른 체크아웃으로 자격 증명을 복사하거나, 관련 없는 변경을 커밋하거나, 쓰기 예산을 초기화하지 않는다.

## 서버 재시작 확인과 측정 구간 복구

실행기가 멈춘 동안 마지막 요청 이후 서비스 노드 3대가 재시작했다.
최초 재시작 감시는 50 VU에서의 재개를 정상적으로 차단했다.

명시적인 유휴 시간 재시작 복구는 다음 조건으로 새 측정 구간을 준비했다.

1. 서버 재시작 시각이 마지막 기록 요청 이후인지 확인한다.
2. 30초 동안 모니터링이 안정적인지 검사한다.
3. 이전 모니터링 기준선을 보관하고 1 VU부터 새 용량 측정을 시작한다.
4. DB 기준선과 공유 쓰기 예산은 유지한다.

이전 성능 측정값은 보존하지만 새 구간에서 더 큰 동시 접속 부하를 허용하는 근거로 쓰지 않는다.

## 코드 검토와 회귀 검증 기록

별도 검토에서 준비 모드만 실행해도 새 측정 구간을 너무 일찍 저장하는 문제를 발견했다.
명시적으로 실행을 요청하지 않았다면 읽기 전용 감사 후 반환하도록 수정했다.

회귀 테스트로 준비 단계가 상태·기준선을 보존하고, 이후 실행이 원래 예산으로 이어지는지 확인했다.
수정 후 실행기 검사 34개가 통과했고 별도 검토자가 수정 사항을 확인했다.
33개·34개는 각각 당시 검사 기록이며 이번 문서 정리의 실행 결과가 아니다.
빈 새 측정 구간에서 다시 중단된 경우에도 자동 진행을 거절하고 수동 감사를 요구한다.

## 저장 컬렉션 확인 기록

사용자는 신규 행동 로그의 주 저장 컬렉션을 `events`로 지정했다.
기존 `simulation` 데이터는 보존하기로 했다.

저장 위치 확인을 위한 일시 중단 시 누적 쓰기 5,261건·행동 로그 3,826건을 대조했고,
처리 중인 요청이나 예산 차이가 없음을 확인했다.
당시 재개 대상은 동일 실행 ID·공유 예산을 사용하는 미완료 50 VU 단계였다.
