# 마이페이지 기능 구현 계획

2026-11-05 마이페이지 개선을 위해 작성한 작업 계획이다.
현재 화면·API·DB 적용·검증 절차는 [마이페이지 안내](../../mypageApi.md)를 따른다.
원문에는 아래 작업별 완료 상태나 전체 테스트 결과가 별도로 기록되어 있지 않다.

## 목적과 구현 방향

예매 내역에서 데이터 관리 영역을 제거하고, 준비 중이던 마이페이지 메뉴를 실제 기능으로 연결한다.
기존 Vue·Pinia와 FastAPI·SQLAlchemy 구조를 유지한다.

찜과 탈퇴는 기존 API를 재사용하고, 찜 상태는 홈과 마이페이지에서 공유한다.
알림 설정은 계정별 DB에 저장한다. MBTI 리포트는 실제 기록을 집계하며 가상 통계를 표시하지 않는다.
알림은 마이페이지 내부 목록으로 제공하고 외부 메일·문자는 발송하지 않는다.

## 작업 범위

1. 개인 기록·같은 MBTI 사용자의 찜 집계, 알림 설정 저장, 계정 격리·삭제,
   예정 공연 필터를 검증할 테스트를 작성한다.
2. 리포트·알림 API의 Pydantic 입력·응답 계약, 알림 설정 테이블,
   Alembic 마이그레이션을 추가한다.
3. 예매 패널에서 데이터 관리와 찜을 분리하고 찜을 독립 패널로 옮긴다.
   홈과 같은 서버 찜 상태를 사용한다.
4. 취향 리포트·알림 설정·알림 목록 패널과 사용자 확인 절차가 있는 탈퇴 패널을 연결한다.
5. 백엔드 전체 테스트, 프론트엔드 빌드, 마이그레이션과 API 호출을 검증한다.

## 주요 검토 항목

- 취소된 예매를 취향 리포트 집계에서 제외하는가
- 다른 계정의 기록이 노출되지 않고 빈 리포트도 처리하는가
- 하트 중복 클릭과 서버 저장 오류에 적절히 대응하는가
- 탈퇴 후 인증·연관 데이터가 올바르게 처리되는가
- 새로고침 후에도 저장한 알림 설정과 찜 상태가 유지되는가

## 검증 범위와 기록

이 문서의 검증 항목은 당시 계획이다. 완료 여부와 실제 적용 시 주의 사항은
[마이페이지 안내](../../mypageApi.md)의 DB 적용·검증 절차와 해당 실행 결과를 확인한다.
이번 문서 정리에서는 기능 테스트·빌드·마이그레이션을 새로 실행하지 않았다.
